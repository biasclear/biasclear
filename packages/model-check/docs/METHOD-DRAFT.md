# Method draft and future live boundary

Model Check asks matched questions and records how the answer is phrased. BiasClear labels structural persuasion patterns; it does not judge factual correctness, personal beliefs, political alignment or model quality. The archived draft deliberately asks for the strongest argument for or against a position. That task can itself induce persuasive wording. Advocacy-pair findings and plain-control findings must remain distinguishable; the draft does not pool them into a neutrality score or rank providers.

The same ordered question IDs and UTF-8 question bytes reach every selected model in separate one-turn requests. This version fixes model-major order and records it. The visible limit is the single reviewed table's common 400 tokens; provider-specific verified low-effort fields are copied exactly and deeply frozen. Unsupported or unknown settings block startup. Different settings syntax does not prove equivalent internal computation, and unspecified sampling defaults remain unknown. A shorter answer, refusal or truncation cannot stand in for a complete zero-mark control.

Current source provenance is official Explain commit `19eebb338ad5676075c4ab5a971eec6d379ef1bc`. All three actual provider rows retain unresolved live-accounting/input-bound evidence, and Sol additionally lacks verified low-effort settings. Registry import is data preparation only. This offline draft has no signed Converse transport, AWS permissions, privacy reader, credential handling, deployment or live adapter.

Future execution requires a separately reviewed integration with the exact persistent shared month/day ledger across all models, fresh reservation before every invoke, model-specific input and total billed reasoning bounds, privacy logging/retention checks and truthful settlement. It must preserve $25/$2.50 ceilings, outstanding charges, deny controls, no retry/fallback and owner-bound approval of the full question/model/settings fingerprint and worst-case cost. A new fake ledger per run cannot substitute for that work.

The current fake ledger rehearses those state transitions only. Its question-byte-plus-50 framing and 400-output allowance is explicitly synthetic. It can retain reservations after unknown usage and record simulated breaches, but it cannot prove a live dollar bound, reconcile prior charges or undo an already billed overrun. Actual cost of this implementation's replay operations is $0.

The approval receipt is a local digest-bound record with an owner-provided reference. It prevents an approved fingerprint from silently being reused after question, registry, model-order or domain drift. It is not an authenticated signature or evidence that an AI may approve itself. Before an actual run, the operator must verify the referenced owner approval independently. This package has not created any receipt for the unapproved archived questions.

The original draft's requested per-model tables are implemented as local Markdown and JSON artifacts with raw final blocks and structural findings beside response/scan status. The incomplete instruction ending “in a table per model and” remains a decision for the owner; this draft adds no scoring, combined statistics or public output to fill that gap.
